# Literature Pass: Which Question / Attribute Types Do Conversational & Interview Recommenders Ask?

Purpose: justify (or amend) the CASPER answerer question universe — **{genre, decade/era, director, actor, composer, writer, franchise}** for the movie (MovieLens) domain. Read-only lit pass, 2026-07-08.

## 1. Evidence table

| Paper / system | Domain(s) | Question types asked | Attribute vocabulary | Answerability / refusal handling |
|---|---|---|---|---|
| **EAR** — Lei et al., WSDM 2020 (2002.09102) | Yelp (business), LastFM (music) | Multi-round: *ask-attribute* vs *recommend-item*; binary and enumerated attribute questions | **Item categories / tags** (Yelp business categories; LastFM music tags). NOT fine-grained crew. Preference estimated jointly over items + attributes | Policy decides *whether* to ask; "reflection" updates model on rejection. No explicit "user can't answer" model — attributes assumed answerable |
| **UNICORN** — Deng et al., SIGIR 2021 (2105.09710) | Yelp, LastFM (same MCR benchmark as EAR) | Unified policy over {when to ask, what to ask, what to recommend}; binary attribute questions | Same tag/category attribute set as EAR; graph nodes = users, items, **attributes (tags)** | No refusal channel; attribute assumed known-or-not from graph |
| **Critiquing recommenders** — Reilly/McCarthy *Dynamic Critiquing* (2004-05); Chen & Pu survey, UMUAI 2012 | Catalog products: **digital cameras, PCs, cars, apartments, wine, restaurants** | User *critiques* a shown item's attribute ("cheaper", "different manufacturer"); unit + **compound critiques** over several attributes at once | Structured product features: price, brand/manufacturer, resolution, memory, cuisine, area. Movie use is rare | Incremental critiquing records history to avoid re-endorsing rejected attribute values; critiques are user-initiated (implicit answerability) |
| **Cold-start interview** — Rashid et al. IUI 2002 ("Getting to know you") | MovieLens (movies) | Present a **sequence of items to rate**; item selection by popularity / entropy / coverage / balanced | **Items (movies), not attributes.** Learns via ratings, not attribute questions | User may mark "don't know" / skip → motivates entropy0 & coverage strategies that avoid unratable (obscure) items |
| **Golbandi et al.** WSDM 2011 (adaptive bootstrapping) | Netflix / movies | Adaptive **decision-tree interview**: each node an item (or category); traverse on **Like / Dislike / Unknown** | Primarily **items**; "Unknown" branch is central. Extensions consider genre/category nodes | "Unknown" is a first-class answer — explicitly models that a user cannot rate an unseen item (askability signal) |
| **PEBOL** — Austin, Korikov, Sanner et al., RecSys 2024 (2405.00981) | MovieLens, Recipe-MPR | LLM-generated **NL yes/no queries over item aspects**; Bayesian belief via NLI between reply and item descriptions | **Open / free-text aspects** mined from item descriptions — no fixed schema (genre/director not enumerated a priori) | Aspect questions grounded in item text so they are answerable by construction; no explicit refusal, but belief tolerates uncertainty |
| **GATE** — Li, Tamkin et al., ICLR 2025 (2310.11589) | Content recommendation, email, moral reasoning | Free-form + **binary yes/no** generated questions ("elicit abstract preferences, easy to answer") | Open vocabulary; not movie-attribute-specific | Explicitly optimizes for questions that are *easy for users to answer*; users report lower effort than prompting |
| **Content-based movie feature studies** — e.g. Gawinecki et al. (SISAP 2021 feature-importance); TMDB/content-CB pipelines; MovieFinder elicitation study | Movies | Feature/attribute similarity + (in MovieFinder) attribute preference elicitation | **genre, cast/actor, director, screenwriter, plot/keywords, year**; MovieFinder used 5: director, casting, genre, star-rating, length. TMDB adds `belongs_to_collection` (**franchise**) | Reported feature ranking (one study): title > genre > cast > screenwriter > director > plot; another finds **director alone** can beat actor/genre. **Composer/soundtrack absent** from standard feature sets |

## 2. Verdict

Our set **{genre, era, director, actor, composer, writer, franchise}** is **largely justified by precedent, with two flags**. *Genre* is universal — it is the one attribute every line of work asks (EAR/UNICORN tags, all content-based movie systems, MovieFinder) and the literature repeatedly finds it the highest-yield, most-answerable attribute. *Actor/cast* and *director* have strong, direct precedent: they are core content features in every movie CB pipeline, and MovieFinder elicited exactly *director* and *casting*; notably several studies rank **director** as unusually informative (sometimes above actor and genre), so keeping both is well-supported. *Decade/era* is supported by the cold-start interview line (temporal/recency signal) and is trivially answerable ("do you like older or newer films?"), a natural low-cardinality axis. *Franchise* has moderate precedent via TMDB-style `belongs_to_collection` metadata and is highly answerable for franchise-heavy MovieLens catalogs, though no elicitation paper asks about it by name. *Writer/screenwriter* has weak-but-real precedent (appears in feature-importance rankings and richer CB feature sets) but is the **least answerable** of the crew attributes — casual users rarely know screenwriters — so treat it as low-priority / expect high refusal. **Composer is the one genuine novelty flag: no elicitation or interview system in the surveyed literature asks about composers or soundtracks, and composer is not even a standard content-based movie feature** (MovieFinder's 5 attributes exclude it; feature-importance studies do not test it). This is a defensible novelty, not a blocker — but it should be expected to have the lowest answerability and should be framed as an exploratory, low-frequency channel rather than a core axis. **Recommended framing:** core/high-answerability = {genre, era, actor, director}; secondary = {franchise, writer}; novel/exploratory = {composer}. Also note a structural gap between our set and the dominant CRS benchmark line (EAR/UNICORN): those systems ask about *coarse tags/categories*, not fine-grained crew — so CASPER's crew-level attribute universe is itself a mild novelty relative to the RL-CRS mainstream, with cleaner precedent coming from the content-based / critiquing traditions than from EAR-style tag questions.
