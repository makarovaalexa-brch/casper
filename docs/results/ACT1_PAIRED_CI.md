## Reproducibility note: the two bandit selectors are not seed-stable

Re-running the identical command reproduces every `entropy0` / `helf` / `popularity` / `pure_entropy` / `random_bank` / `random_catalog` / `eddi_ig` cell **exactly** (bit-level, to 1e-9) but reproduces **no** `glm_ucb` or `thompson` cell exactly. Cause: `ials._fit_model` constructs `AlternatingLeastSquares(...)` with **no `random_state`**, so the frozen iALS basis `Y` that `belief_mf` hands both bandits is re-drawn on every process. The selectors' own seeds (`ts_seed=98765`, `alpha=1.0`) are honoured; the *posterior they are seeded against* is not.

Consequence for these CIs: the pairing is still valid and the intervals are still correct **conditional on this run's basis** — both arms of every comparison come from one process and the static comparator is exactly reproducible. But the bandit rows carry an additional basis-to-basis variance component that a within-run paired bootstrap cannot see. The two runs available give a direct read on its size (below): up to $\pm.0026$, which is comparable to the CI half-widths. **Any chapter claim about a `glm_ucb` or `thompson` number to four decimals is currently unreproducible**; the fix is one `random_state=` argument plus a re-run.
